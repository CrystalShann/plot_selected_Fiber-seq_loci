From LCL track files to a locus experiment

This guide uses the package’s subset of the actual AL6_bc2162_19093 and AL8_bc2170_19151 LCL files at ALAS1 and PRDX1. It shows the input fields, coordinate conversions and R objects at each step. These are small processed track files, with matching complete records and regenerated tabix indexes. The subset is capped at 100 full-span reads per sample per locus; the available totals are 18 reads at ALAS1 and 16 at PRDX1.

All analysis runs in R. The package expects processed tracks rather than BAM or FASTQ files. See Select Fiber-seq loci: ALAS1 with and without clustering for the full set of clustered and unclustered panels.

1. Copy the example into a writable directory

example <- example_data()

#> [1] "provenance.json" "regions.tsv"     "samples.tsv"     "SHA256SUMS"

example$directory is a temporary writable copy. To keep the inputs, supply a persistent destination, for example example_data("my-LCL-example"). samples.tsv and regions.tsv describe the files under tracks/. provenance.json records original source paths and selected read IDs; SHA256SUMS records checksums. The subset-generation script is installed at system.file("scripts", "build_example.py", package = "selectFiberseqLociWorkflow"). The examples below use only this copied dataset and installed package files.

Only {sample_name} and {chr} are supported placeholders. The actual LCL sheet uses sample-specific folders and {chr}. A single genome-wide file per sample can instead be supplied without {chr}. Each supplied track must be bgzip-compressed, sorted and tabix-indexed, with its .tbi beside it.

This is the same LCL sheet expressed using both placeholders:

template_table <- sample_table
for (track in c("m6a", "nucleosome", "tf", "fire")) {
    template_table[[track]] <- paste0("tracks/{sample_name}/", track,
        ".{chr}.bed.gz")
}
template_samples <- make_sample_sheet(template_table,
    base_dir = example$directory)

3. Regions: declare the coordinate convention

The actual regions.tsv is a headered table. Its start and end use BED coordinates: zero-based start, end excluded. Its tss is one-based. Read the table first, then declare coordinate_system = "bed":

region_table <- read.delim(file.path(example$directory, "regions.tsv"))
knitr::kable(region_table[, c("region_id", "chr", "start", "end",
    "strand", "tss")])
region_id chr start end strand tss
ALAS1 chr3 52197159 52199159 + 52198160
PRDX1 chr1 45520883 45522883 - 45521884 
regions <- prepare_regions(region_table, coordinate_system = "bed")
regions
#> GRanges object with 2 ranges and 2 metadata columns:
#>         seqnames            ranges strand |   region_id       tss
#>            <Rle>         <IRanges>  <Rle> | <character> <numeric>
#>   ALAS1     chr3 52197160-52199159      + |       ALAS1  52198160
#>   PRDX1     chr1 45520884-45522883      - |       PRDX1  45521884
#>   -------
#>   seqinfo: 2 sequences from an unspecified genome; no seqlengths
alas1 <- regions["ALAS1"]

The ALAS1 interval [52197159, 52199159) becomes chr3:52197160-52199159 in R: 2,000 bases, one-based inclusive. PRDX1 is on the minus strand, but its genomic start is still less than its end. Coordinates are not reversed for minus-strand loci.

Input to prepare_regions() Coordinate convention Details
GRanges One-based inclusive Preserves sequence information; names identify regions
data.frame / DataFrame Explicit "bed" or "one_based" Required chr, start, end; optional region_id, strand, tss
Headerless BED path Zero-based, half-open First three fields are contig/start/end; field 4 is region ID and field 6 is strand
"chr3:52197160-52199159" One-based inclusive Plain coordinate string; no TSS or gene metadata inferred
annotation = "file.gtf" or "file.gff3" One-based annotation coordinates Transcript features define TSSs; see annotation examples below
Custom single-base TSS BED Zero-based, half-open Optional bed_annotation = "gencode_custom"; name field is geneID;annotation;geneName

Do not pass a headered regions.tsv directly as a BED filename. flank_bp expands annotation-derived TSSs or custom TSS BEDs; ordinary coordinate inputs already specify the full analysis interval.

The following representations all describe the same ALAS1 interval:

one_based <- region_table[region_table$region_id == "ALAS1", ]
one_based$start <- one_based$start + 1L
from_one_based <- prepare_regions(one_based, coordinate_system = "one_based")
from_string <- prepare_regions("chr3:52197160-52199159")
from_granges <- prepare_regions(alas1)

bed_file <- tempfile(fileext = ".bed")
write.table(data.frame(chr = "chr3", start = 52197159, end = 52199159,
    name = "ALAS1", score = 0, strand = "+"), bed_file,
    sep = "\t", quote = FALSE, row.names = FALSE, col.names = FALSE)
from_bed <- prepare_regions(bed_file)

for (r in list(from_one_based, from_string, from_granges, from_bed)) {
    stopifnot(as.character(seqnames(r)) == "chr3",
        start(r) == start(alas1), end(r) == end(alas1))
}

# Exported region tables also use BED start/end and one-based TSS.
saved_regions <- tempfile(fileext = ".tsv")
prepare_regions(regions, output = saved_regions)
#> GRanges object with 2 ranges and 2 metadata columns:
#>         seqnames            ranges strand |   region_id       tss
#>            <Rle>         <IRanges>  <Rle> | <character> <numeric>

    identical(end(round_trip), end(regions)),

Contig names must match exactly between regions and track indexes, including case. No chromosome prefix conversion or genome-assembly conversion is done.

4. Inspect a real record from each LCL track

The format is declared in the sample sheet, not guessed from the filename or from whether the user ran fibertools or FiberHMM. These are the supported formats; the LCL subset uses the four marked in the final column.

Nucleosome bed12_fibertools BED12 blocks, including terminal sentinel blocks Yes
Nucleosome bed13_fiberhmm BED12 plus per-block scores; no sentinel removal No; supported alternative
TF bed15_fiberhmm_tf BED12 plus block scores and left/right edge-score vectors Yes

For BED12, fields 2 and 3 are the alignment’s BED bounds; blockStarts are offsets from field 2. Block vectors have blockCount entries. Fibertools’ first and last blocks are sentinels and are removed before calls are used. m6A interior blocks must each be one base wide. Reads with no interior m6A calls in the selected region still contribute to the denominator if they span the region.

For the actual TF BED15, field 13 contains scores for individual blocks. min_tf_score = 50 filters those scores, not field 5. Retained TF width classes are [10,30), [40,60) and [60,80) bp. BED6 TF intervals are expected to be score-filtered already; the same width classes apply. The default retained nucleosome widths are 130 through 160 bp inclusive.

FIRE records are per-read intervals, joined by their original RID. The trailing tag may contain legacy haplotype labels in these source files; the package does not use that field to phase or split reads. Allele-specific RDS inputs are not needed. Optional track RIDs must match the m6A RIDs within each sample; records for reads excluded by full-span filtering do not enter the result.

5. Validate and analyze

validate_inputs() checks file/index availability, the required m6A contigs, and declared record structure in sampled records. Parsing during analysis performs further checks on records in the requested region. It does not certify every record in a whole-genome file.

validate_inputs(samples, regions)
validate_inputs(template_samples, regions)

# An expected error: a supported TF format cannot be used for m6A.
bad_samples <- samples
bad_samples$m6a_format <- "bed15_fiberhmm_tf"
tryCatch(validate_inputs(bad_samples, alas1), error = conditionMessage)
#> [1] "Unsupported/missing m6a_format; choose bed12_fibertools"

6. How GRanges, the assay and colData agree

results is a named SimpleList. Each element is a RangedSummarizedExperiment with genomic bases in rows and reads in columns. assay(x, "m6a") is a sparse binary matrix. A zero means no observed m6A call at that genomic position, not an experimentally measured unmethylated adenine.

Component Structure Alignment with the assay
rowRanges(x) Single-base GRanges, one-based inclusive One range and matching row name per assay row
colData(x) DataFrame of read metadata One row and matching RID per assay column
colData(x)$read_range GRanges of full alignments One alignment per assay column; agrees with chr, start, end, strand
colData(x)$footprints GRangesList One list element per read, with RID, track and class metadata on its intervals
metadata(x) List Original region, sample sheet, QC, parameters and optional clustering provenance

The column ID is sample_name::original_RID, so the same original RID in two samples does not collide. All in-memory alignment and footprint coordinates are one-based inclusive. Stored footprints can extend beyond the locus if an original call overlaps its boundary.

A supplied nucleosome or TF track that has no retained footprints in the region raises the warning:

no footprints called in the selected region

Analysis continues, and metadata(x)$empty_footprint_tracks records the affected track types with no retained calls across the supplied samples. This can also happen after size or score filtering. A supplied nonexistent file or missing .tbi is instead an input error.
